# Dolwood — буковая доска и мебельные заготовки

Сайт для закупщиков мебельных фабрик и производств. Только бук. Next.js 15, статический экспорт; содержимое страниц доступно без JavaScript.

## Запуск

```sh
npm ci
npm run dev
npm run build
python3 scripts/check-export.py
```

Готовые файлы находятся в `out/`. `next start` не предназначен для этого статического экспорта. Для локального просмотра: `python3 -m http.server 4173 --directory out`.

## Страницы и содержание

| Страница | Назначение |
|---|---|
| `/` | Доска как основное предложение, цены, запрос, доставка, заготовки, производство, FAQ и контакты |
| `/bukovaya-doska/` | Характеристики, цены, выбор сорта и размеров, запрос партии |
| `/zagotovki-iz-buka/` | Детали и декор, исходные данные для расчёта, запрос по чертежу |
| `/dostavka-i-oplata/` | Предоплата, самовывоз и перевозка ТК |

Собственные формы для доски и деталей отправляют запросы в `/api/leads`. Сервер записывает их в SQLite, затем возвращает подтверждение. Обязателен телефон или email; параметры заказа необязательны. Загрузки чертежей пока нет: менеджер запросит файл при общении.

## Домен и публикация

Адрес для canonical, Open Graph, JSON-LD, sitemap и robots задаётся в одном месте при сборке:

1. `NEXT_PUBLIC_SITE_URL` — полный публичный адрес без завершающего `/`, включая подпапку при её использовании.
2. При отсутствии переменной: домен из `public/CNAME`.
3. При GitHub Actions без CNAME: `https://owner.github.io/repository`, согласно `GITHUB_REPOSITORY`. Для репозитория `owner.github.io` подпапки нет.
4. При локальной сборке по умолчанию используется **неподтверждённый** `https://dolwood.ru`. Перед публикацией подтвердите домен.

Для собственного домена на GitHub Pages добавьте `public/CNAME` с доменным именем: это также выключит подпапку ресурсов. Для другого статического хостинга задайте `NEXT_PUBLIC_SITE_URL` и собирайте без `GITHUB_REPOSITORY`.

```sh
NEXT_PUBLIC_SITE_URL=https://example.ru npm run build
python3 scripts/check-export.py https://example.ru
```

Проверка экспорта сверяет четыре страницы, уникальные заголовки и описания, H1, canonical, JSON-LD, sitemap, наличие ресурсов, внутренние ссылки и якоря. Для сборки в подпапке укажите её в адресе проверки.

## Действия после публикации

- Подтвердить конечный домен и доступность всех четырёх страниц по HTTPS. При смене домена настроить перенаправления на хостинге.
- Добавить подтверждённый точный адрес самовывоза, график, реквизиты и реальные фотографии продукции/производства. Сейчас есть только городской округ; точный адрес не выдуман. Микроразметка Organization не изображает полный адрес LocalBusiness.
- Подключить Яндекс.Вебмастер и Google Search Console, отправить `sitemap.xml`, проверить индексирование. Доступ к аккаунтам в этом изменении не использовался.
- Подключить собственный счётчик Яндекс.Метрики по инструкции ниже.
- Вести журнал обращений: направление, объём, источник, КП, оплаченный заказ, повторная закупка. По нему оценивать продвижение доски и заготовок.

SEO-структура опирается на отдельные полезные страницы и понятные внутренние ссылки: [рекомендации Яндекса по структуре](https://yandex.ru/support/webmaster/ru/recommendations/site-structure). Метаданные задаются средствами [Next.js Metadata](https://nextjs.org/docs/app/api-reference/functions/generate-metadata). Полные данные организации понадобятся для расширения до [LocalBusiness](https://developers.google.com/search/docs/appearance/structured-data/local-business).

Внешняя публикация и регистрация в поисковых сервисах ещё не выполнены. Код Метрики готов; без номера собственного счётчика сбор данных выключен. SEO-подготовка не гарантирует конкретные позиции в выдаче.

## Яндекс: SEO и аналитика

SEO подготовлено для Яндекса: отдельные страницы доски, заготовок и доставки; понятные заголовки, характеристики, регион производства и контакты; canonical и sitemap. В `robots.txt` есть группа Yandex и `Clean-param` для рекламных меток, чтобы параметры кампаний не создавали отдельные индексируемые адреса. Рекламные метки продолжают использоваться для атрибуции в Метрике. Регион назначается в Яндекс.Вебмастере после подтверждения сайта: [справка по региональности](https://yandex.ru/support/webmaster/ru/site-geography/site-region.html). Точный адрес и карточку Яндекс Бизнес добавьте по реальным данным производства.

В первом экране нет предоплаты и ограничения партии. Цены доступны через раскрываемый блок, условия оплаты — на странице доставки. Для доски и деталей используются формы в дизайне сайта. Обязателен один контакт; параметры заказа необязательны. Никаких фиктивных скидок, отзывов или обещаний наличия не добавлено.

### Подключение собственного счётчика

1. Создайте счётчик в Яндекс.Метрике или используйте существующий для этого сайта.
2. Скопируйте `.env.example` в `.env.local` и укажите `NEXT_PUBLIC_YANDEX_METRICA_ID` — только числовой номер счётчика. Для GitHub Pages установите одноимённую repository variable в Settings → Secrets and variables → Actions → Variables; workflow уже передаёт её при сборке.
3. В `NEXT_PUBLIC_YANDEX_VERIFICATION` укажите код подтверждения из Вебмастера (значение `content`, не весь HTML-тег), если подтверждаете сайт через метатег. Пересоберите и опубликуйте сайт.
4. В счётчике создайте цели типа **JavaScript-событие** с идентификаторами из таблицы. Код отправляет их через `reachGoal`.
5. После публикации проверьте поступление посещений и достижение целей в своём счётчике. Локальные проверки на localhost и 127.0.0.1 исключены. При отсутствии номера библиотека Метрики не загружается.

| Идентификатор цели | Что считается |
|---|---|
| `request_board` | Клик по кнопке перехода к запросу доски |
| `request_parts` | Клик по кнопке перехода к расчёту деталей |
| `request_start` | Первое изменение поля формы, один раз на блок за просмотр страницы |
| `request_saved` | Получено подтверждение успешной записи заявки в собственную базу |
| `request_contact` | Зарезервировано для переходов к каналам связи из формы; отправку в базу считает `request_saved` |
| `request_copy` | Успешное копирование текста запроса |
| `contact_phone` | Клик по номеру телефона |
| `contact_whatsapp` | Переход в WhatsApp |
| `contact_telegram` | Переход в Telegram |
| `contact_email` | Открытие почтового приложения |

Параметры целей: `placement` (hero, wholesale, blanks, request, contacts, header, footer, mobile, floating), `product` (board/parts, если известен), `channel`, `page`. Цели каналов и `request_contact` пересекаются намеренно: первая показывает канал по всему сайту, вторая — переход из блока запроса. Их нельзя складывать как уникальные заявки. Метрика фиксирует действия и успешную запись в базу; договор и оплату отмечайте по фактическим данным продаж.

Счётчик асинхронный. `defer: true` + `hit` отслеживают просмотры без двойной отправки при переходах Next.js. Вебвизор отключён, поля и текст запроса помечены `ym-hide-content` / `ym-disable-keys`; в цели не передаются введённые размеры, город, комментарии или текст сообщения. Автоматический учёт внешних ссылок отключён, чтобы не отправлять URL с текстом запроса; каналы связи учитываются отдельными целями. Ошибка или блокировка Метрики не мешает обращениям.

Проверки: `node scripts/check-analytics.cjs` и `python3 scripts/check-export.py` после сборки. В тестах используется фиктивный номер только в изолированном процессе со stub-функцией `ym`; сетевых запросов нет.

Источники: [Clean-param](https://yandex.ru/support/webmaster/ru/robot-workings/clean-param), [SPA и просмотры в Метрике](https://yandex.ru/support/metrica/ru/code/counter-spa-setup), [reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal).

## Собственные формы и база заявок (12 октября 2026)

Яндекс Форма заменена собственными формами в дизайне Dolwood на главной, странице доски и странице заготовок. Телефон или email вводится в одно обязательное поле. Параметры партии/деталей раскрываются по желанию. При ошибке ввод остаётся, можно повторить отправку. Пока сервер не подтвердит запись, сайт не показывает «Заявка принята» и не отправляет цель `request_saved`. Повторный запрос с теми же данными и ключом не создаёт второй заказ.

Jivo `IPo9Nx4dIu` сохранён. Заявки формы не передаются в Яндекс, Jivo, почту или другие сервисы. Переписка в Jivo отдельно обрабатывается самим Jivo. Созданная ранее Яндекс Форма остаётся в аккаунте владельца, на сайте не используется.

### Локальный запуск

Нужен Node.js 22.18+; для размещения используйте актуальную LTS-версию (Docker использует Node 24).

```sh
npm ci
npm run build
npm run serve:leads
```

Откройте http://127.0.0.1:4174/#request-board — это сайт вместе с API, не прежний статический просмотр на 4173. База автоматически создаётся в `server/data/leads.sqlite`, за пределами публичной папки `out`. Файлы базы исключены из Git и Docker-контекста. Не удаляйте папку `server/data` при обновлениях.

### Просмотр и резервные копии

Публичного списка заявок нет. Выгрузка доступна только через доступ к серверу. Открывайте CSV в табличном редакторе:

```sh
node server/export.mjs /private/tmp/dolwood-leads.csv
node server/backup.mjs /private/tmp/dolwood-backup.sqlite
```

Выберите новый путь при повторной выгрузке. Файлы создаются с ограниченным доступом. При резервном копировании используется SQLite Backup API, работающий и при запущенном сервере. Переносите резервные копии в закрытое хранилище за пределами сервера. Восстанавливайте при остановленном приложении. Не копируйте только основной SQLite-файл из работающей базы в режиме WAL.

### Размещение

Программное обеспечение бесплатно; для постоянной работы нужен сервер/хостинг и HTTPS. У владельца хостинга пока нет, публичное размещение не выполнено. Для старта предлагается один сервер с сайтом и SQLite: минимум сервисов и резервная копия небольшого файла. Будущая нагрузка, несколько серверов и кабинет менеджеров могут потребовать PostgreSQL.

Подготовлены `Dockerfile` и `compose.yaml` с постоянным Docker volume `leads`. Перед публичным размещением:

1. Укажите подтверждённый домен в `NEXT_PUBLIC_SITE_URL` и точный origin сайта в `ALLOWED_ORIGINS` (например, `https://your-domain.ru`, без пути и завершающего `/`).
2. Запустите `docker compose up -d --build`. Контейнерный порт привязан только к loopback сервера.
3. Настройте HTTPS reverse proxy на `127.0.0.1:4174`. Если прокси безопасно добавляет реальный IP последним в `X-Forwarded-For`, задайте `TRUST_PROXY=true`; иначе оставьте false. Без доверия прокси лимит считается по IP прокси.
4. Настройте резервные копии и проверьте отправку на публичном домене. В образ базы не включаются, volume не удаляется при пересборке. Не выполняйте `docker compose down -v` при обновлении.

Если сайт останется на GitHub Pages, потребуется отдельный API на сервере: задайте его HTTPS-адрес в `NEXT_PUBLIC_LEADS_API_URL` при сборке, а origin GitHub Pages добавьте в `ALLOWED_ORIGINS`. GitHub Pages сам не запускает API и базу.

Защита: серверная проверка полей и типа тела, SQL с параметрами, ограничение размера запроса 16 КБ, лимит попыток 10 в минуту на IP, список разрешённых origins, запрет публичного чтения заявок. CORS не заменяет защиту от ботов; при спаме можно подключить дополнительную проверку. Контакт и параметры не пишутся в журналы приложения и цели Метрики. Публичных ключей к базе в браузере нет.

Номер счётчика Метрики пока не предоставлен: разметка `request_start` / `request_saved` подготовлена, отправка событий отключена без номера.
